# Science Quest 2.0 — integration foundation

This branch adds the first backend foundation without overwriting the current playable `index.html`.

## Files
- `supabase/migrations/202611100001_science_quest_2.sql`: groups, custom worlds, inventory, async trades, weekly/monthly quest definitions and claim-once records; RLS and restricted RPCs.
- Existing game remains unchanged on this branch.

## Important security notes
1. The current game has a Supabase publishable key in browser code. That key is not a secret; security must come from RLS, grants and server-side checks.
2. Never put the Supabase `service_role` / secret key in `index.html`, JavaScript, or a public repository.
3. Admin access in this migration uses the trusted JWT claim `app_metadata.role = "admin"`. Set it only from Supabase Dashboard / trusted server. Never use `user_metadata` for authorization.
4. The existing account system maps usernames to synthetic email addresses. This migration assumes those existing Supabase Auth users and their UUIDs.
5. Inventory writes are intentionally RPC-only. Do not add client INSERT/UPDATE grants to `sq_inventory`.

## Apply
1. Back up the Supabase project.
2. Open Supabase Dashboard → SQL Editor.
3. Run `supabase/migrations/202611100001_science_quest_2.sql`.
4. Promote an administrator by setting that user's **app_metadata** role to `admin` from a trusted admin surface. Do not let a browser client set this claim.
5. Run RLS tests before exposing the new screens.

## Frontend API calls
The current `index.html` already defines `sb(path, options)`, which adds the publishable key and the signed-in user's access token. The following calls can be made from its existing script:

```js
// Groups and published worlds
const groups = await sb('/sq_groups?select=*&order=created_at.asc');
const worlds = await sb('/sq_worlds?select=*&published=eq.true&order=created_at.asc');

// Admin-only creation (RLS rejects non-admins)
await sb('/sq_groups', {
  method: 'POST',
  body: JSON.stringify({ name: '5 класс', created_by: AU.id })
});
await sb('/sq_worlds', {
  method: 'POST',
  body: JSON.stringify({
    group_id: groupId,
    name: 'Мир физики',
    description: '...',
    payload: levelPayload,
    published: true,
    created_by: AU.id
  })
});

// Read own inventory
const inventory = await sb('/sq_inventory?select=item_id,quantity');

// Offer a trade while the other player is offline
const tradeId = await sb('/rpc/sq_create_trade', {
  method: 'POST',
  body: JSON.stringify({
    p_recipient: recipientUserUuid,
    p_offer: [{ item_id: 'skin_ice', quantity: 1 }],
    p_request: [{ item_id: 'skin_fire', quantity: 1 }]
  })
});

// Recipient accepts/rejects later; exchange is one database transaction
await sb('/rpc/sq_respond_trade', {
  method: 'POST',
  body: JSON.stringify({ p_trade: tradeId, p_accept: true })
});

// Read pending offers
const offers = await sb('/sq_trades?select=*&status=eq.pending&order=created_at.desc');

// Claim once for the current UTC week/month; database calculates period boundary
await sb('/rpc/sq_claim_quest', {
  method: 'POST',
  body: JSON.stringify({ p_quest_id: 'weekly_science', p_period: 'weekly' })
});
```

## Not yet wired / must be completed before production
- Replace `rWorlds()` and multiplayer level selectors so they read `sq_groups` / `sq_worlds`, instead of the built-in `W` array. Do not delete the old `W` array until all legacy level references are migrated.
- Add admin UI for group/world creation and a student group/world browser.
- Add inventory-to-`sq_inventory` migration for existing `S.sk` skins. Existing localStorage inventory is not authoritative; import must be validated and deduplicated server-side.
- Add a trade inbox/outbox UI, player lookup, item picker and notifications.
- Quest reward claiming is one-per-period, but quest progress is **not yet generated by trusted game events** in this foundation. Do not expose rewards as earned until an Edge Function / trusted database routine validates a completed level and increments `sq_quest_progress`. Never allow arbitrary client writes to progress.
- Existing game uses local save and a broad profile save object. Audit/replace that flow before considering account saves secure; RLS on the new tables does not automatically secure old tables.
- Add pgTAP tests for allow/deny cases and run `supabase test db`. The migration has not been executed against the live project or integration-tested.

## Why this is a foundation, not a finished release
The repository's current game is a large single-file app with legacy tables and flows. Replacing the entire file without a complete read/compile/test cycle risks breaking gameplay or losing existing features. This branch isolates the database schema first so it can be reviewed and applied safely.
